# 트랜잭션 정책 테이블

## 목적
작업별 트랜잭션 범위, 타임아웃, 실패 처리 정책을 표준화한다.

## 정책 표
| 작업 | 트랜잭션 범위 | 권장 타임아웃 | 실패 시 처리 |
|---|---|---:|---|
| 입찰 매칭 잠금/검증 | 내부(DB) | 5초 | 롤백 |
| 입찰 상태 전이 | 내부(DB) | 5초 | 롤백 |
| 주문 생성 | 내부(DB) | 5초 | 롤백 |
| 체결 이벤트(`trade_events`) 저장 | 내부(DB) | 5초 | 롤백 |
| 감사로그(`audit_logs`) 저장 | 내부(DB) | 5초 | 롤백 |
| 결제 이벤트 보강(`payment_events`) | 외부(AFTER_COMMIT) | 10초 | 재시도 큐 |
| PG 승인/확인 호출 | 외부(AFTER_COMMIT 또는 결제 단계) | 30초 | 재시도/보상(정책 확정 전 임시 재시도) |
| 알림 발송 | 외부(비동기) | 10초 | 실패 로그 후 무시 |
| Redis 캐시 무효화 | 외부(비동기) | 1초 | 실패 로그 후 무시(다음 조회 시 DB fallback) |

## 구현 규칙
- 체결 트랜잭션 메서드: `@Transactional(timeout = 5)`
- 외부 작업은 트랜잭션 내부 금지
- 외부 작업은 `@TransactionalEventListener(phase = AFTER_COMMIT)` 또는 별도 비동기 워커 사용
- 타임아웃 초과는 실패로 간주하고 정책에 따라 롤백/재시도 적용

## 운영 관찰 포인트
- 체결 트랜잭션 평균/최대 실행시간
- 롤백 건수와 원인 분류(락 대기, 제약 위반, 타임아웃)
- AFTER_COMMIT 후처리 실패율 및 재시도 성공률
