# 체결 성공 경계 정의

## 목적
거래 체결 과정에서 "성공"의 범위를 고정해, 운영/장애/재시도 시 일관된 판단 기준을 유지한다.

## 최종 정의
**체결 성공 = DB 트랜잭션 커밋 성공 시점**이며, 아래 항목이 모두 완료된 상태를 의미한다.

1. 매수/매도 입찰 상태 전이 (`PENDING -> MATCHED`)
2. 주문 생성 (`orders`, 상태 `PAYMENT_PENDING`)
3. 체결 이벤트 저장 (`trade_events`)
4. 감사 로그 저장 (`audit_logs`)

## 경계 밖(체결 성공 판정에 포함하지 않음)
- 결제 승인 요청/확인(PG 외부 호출)
- 결제 이벤트 후처리(`payment_events`의 비핵심 보강 작업)
- 알림 발송(Slack/메일)
- 캐시 무효화/재적재(Redis)

## 실패 처리 규칙
- `trade_events` 저장 실패: **체결 실패(전체 롤백)**
- `audit_logs` 저장 실패: **체결 실패(전체 롤백)**
- 체결 커밋 이후 `payment_events` 후처리 실패: **체결 성공 유지 + 재시도 큐 처리**

## 구현 원칙
- 체결 핵심 로직은 단일 트랜잭션으로 처리
- 외부 호출/부가 작업은 `AFTER_COMMIT` 비동기 후처리로 분리
- "체결 성공" 상태는 DB 데이터로만 판정

## 예시 흐름
1. `executeMatch(...)` 트랜잭션 시작
2. 입찰 상태 변경 + 주문 생성 + `trade_events`/`audit_logs` 저장
3. 커밋 성공 -> 체결 성공 확정
4. `AFTER_COMMIT` 핸들러에서 결제 이벤트/알림/캐시 후처리 수행
